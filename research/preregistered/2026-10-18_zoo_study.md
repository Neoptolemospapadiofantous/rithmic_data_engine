# 2026-10-18 — model-zoo validation + feature selection (pre-registered before any run)

Scope: the dashboard's 14 analysis models in `~/Desktop/bot/ui/services/models/` (base.py + day_type, trade_filter,
adaptive_risk, breakout, bandit, exit_model, regime, fill_quality, policy_search, sequence, exit_optimizer,
signal_meta, overlay_uplift, fill_cost). None of them is wired to the executor; this study decides which ones carry
out-of-sample signal and which features in each one actually work. Harness: `~/Desktop/bot/python/research/zoo_study.py`
(`cd ~/Desktop/bot && .venv/bin/python -m python.research.zoo_study`). Postgres is read **only**
(`cpp_engine._schema_ensured` is forced true so the connection helper's idempotent ALTER never runs; no model's
`train()` is ever called — it persists artefacts under `data/models/` and `trade_filter.train()` rewrites
`trade_context`). The models themselves are not modified; each model's own `dataset()` / feature functions are
imported and reused. Outputs: `research/zoo_study/<model>.json` + `research/zoo_study/report.md`.

## What the data allows (measured 2026-10-18 before writing the rules)

| source | range | consequence |
|---|---|---|
| `bars_1m` NQ | 2010-07-01 → 2026-10-17 (5.2 M bars; Databento OHLCV, MBO 2023-03+, collector 2026-09+) | day_type, sequence, regime have 16 years |
| `ticks` NQ | 2026-09-19 → now | breakout, exit_model, policy_search, exit_optimizer have 4 weeks |
| `paper_trades` label `tradeify` (the forward test) | 2026-09-21 → 2026-10-16, 134,366 trades, 23 sessions, 6,655 strategy ids | every trade-based model has 4 weeks |
| `trade_context` | 111,224 paper (tradeify) + 86 live rows, same 4 weeks | trade_filter / adaptive_risk / fill_quality features |
| `live_trades` with slippage | 85 | fill_quality |
| `paper_signals` taken, base ids | 19,986, same 4 weeks | signal_meta |
| `bbo` | 2026-09-22 → now | book features NaN before that |

So the registered scheme splits the zoo in two: **bars-based models get the yearly walk-forward** (2010 → 2026);
**every trade/tick-based model has 23 sessions**, far below the ≥ 6 training months the monthly scheme needs, and
is therefore **NOT VALIDATED (short history)** under this registration. For those we still run an *exploratory*
weekly walk-forward (below) so the report says what 4 weeks look like, but an exploratory pass is explicitly not a
pass: the verdict column stays "not validated — short history (exploratory weekly: …)".

## Common protocol (fixed here, identical for every validated model)

- **Walk-forward.** ≥ 3 years of data → yearly: for each test year Y, train on every row dated < Y; the first
  test year is the one after at least two full training years (bars: 2013). < 3 years → monthly with ≥ 6
  training months. < 7 months → *exploratory weekly only*: test each ISO week after ≥ 2 training weeks
  (with 4 weeks of data: train W39–40 → test W41, train W39–41 → test W42). Rows are time-ordered by the
  model's own timestamp (day / entry_time / signal ts / bar time); grouped data (exit_model samples) is split
  by trade, never by sample.
- **OOS metric** = the metric pooled over all test folds (per-fold values also stored). Classifiers: AUC
  (binary) or accuracy + trend-vs-rest AUC (3-class, accuracy is the pass metric). Regressors: MAE (L1
  models) or pinball loss at the model's own quantile (quantile models). Decision models: net P&L per
  decision. Baseline = training-fold majority class (accuracy), 0.5 (AUC), training median/mean (MAE), training
  quantile (pinball), "do nothing / live rule" (decisions).
- **Estimator** = the model's own LightGBM objective and `LGB_PARAMS`, with a **fixed** 120 boosting rounds
  (the models early-stop on the hold-out, which leaks; fixed rounds removes it). The models' `FeatureSelector`
  is NOT applied — all raw `FEATURES` go in, and selection is done by the permutation test below.
- **Shuffled-label control.** Per fold, 20 refits with the training labels permuted within that fold (seeds
  0–19), each scored on the same test fold; refit *i*'s OOS predictions are pooled across folds exactly like
  the real model's, giving 20 pooled control metrics. Percentile = share of controls the real metric beats
  (higher-is-better metrics: real > control; lower-is-better: real < control).
- **Pass rule.** PASS only if the real pooled OOS metric beats ≥ 95 % of the 20 shuffled-label refits (i.e. ≥ 19
  of 20) **and** is better than the trivial baseline. Otherwise FAIL. Models that cannot be run this way →
  "not validated" + reason.
- **Feature selection** (validated models and, for orientation, exploratory ones). Permutation importance on
  the pooled OOS predictions, 10 seeds: importance = degradation of the primary OOS metric when that feature's
  column is permuted within the test rows, per fold model, averaged over seeds. The pooled test rows are cut
  into three equal time-thirds; a feature **works** if its importance > 0 in ≥ 2 of 3 thirds **and** its
  whole-test importance exceeds the same feature's importance under the shuffled-label model (mean over the
  first 5 shuffled refits, 3 seeds each). Then one refit on the working features only, same walk-forward,
  and its pooled OOS metric is reported next to the all-features metric (no further selection).
- **Time-box.** Each model's full procedure is budgeted at ~15 min wall. A model that would exceed it runs
  with fewer shuffled refits / seeds (the report says so) or is marked not validated.

## Per-model registration

1. **day_type** — predicts trend / mixed / range (|close−open|/range of the RTH session ≥ 0.5 / ≤ 0.25) for
   the coming RTH session. Dataset: the model's own `_sessions` / `_rth_stats` / `_on_stats` / `dataset()`
   feature code over `bars_1m` 2010-07 → 2026-10. Two documented deviations, decided here: (a) `minute_bars`
   is swapped for a per-calendar-year loader with the same SQL shape and row dict (5.2 M bars at once would not
   fit next to the box's other work; years are loaded with a 4-day overlap so the prior-day chain is intact);
   (b) the `good_days` tick-coverage filter is bypassed — it is defined on `ticks`, which exist only since
   2026-09-19, so applied literally it would reduce 16 years to ~20 days; the Databento bars are complete.
   Features: the 9 in `FEATURES` (on_range, on_vol, on_eff, gap, prev_range, prev_close_pos, prev_trend_score,
   dow, on_minutes). Estimator: LightGBM multiclass, `min_data_in_leaf = max(3, n_train // 15)`, 120 rounds.
   Metric: accuracy (pass metric) vs training-majority accuracy; trend-vs-rest AUC reported alongside.
   Walk-forward: yearly, test 2013 … 2026. Shuffled: 20 refits per fold.
2. **trade_filter** (`ui/services/trade_model.py`) — p(win) and expected P&L at entry from `trade_context`.
   Dataset: `trade_model.load_dataset(days=40)` (its own filters: live or label tradeify, no INCIDENT/DRILL/_TEST/
   _dry). Features: the 72 in `trade_model.FEATURES` (15 context numerics, 7 one-hots, 50 `mtf:` multi-timeframe
   features). Estimator: LightGBM binary (primary) and regression_l1 (secondary), 120 rounds. Metric: AUC vs 0.5
   (primary); P&L MAE vs training median (secondary, reported). Short history → **not validated**; exploratory
   weekly walk-forward reported. Note recorded in advance: the 111 k rows are 6,655 near-identical fleet
   siblings trading the same sessions, so even the weekly folds are heavily correlated — any exploratory AUC is
   an upper bound.
3. **adaptive_risk** — stop that survives (quantile-0.8 of |MAE| + 0.25) and MFE (median). Dataset:
   `adaptive_risk.dataset(days=40)` (closed trades with MAE/MFE + context; this is tradeify + live only because
   only those carry context). Features: its 10 `FEATURES`. Estimators: LightGBM quantile α = 0.8 (primary) and
   regression_l1 (secondary), 120 rounds. Metrics: pinball-0.8 loss vs the constant training 0.8-quantile
   (primary); MFE MAE vs training median (secondary). Short history → **not validated**; exploratory weekly.
4. **breakout_failure** — at an opening-range cross, does price re-enter within 5 min. Dataset:
   `breakout.dataset(days=40)` (its own tick mining, `good_days` applies as written — ticks exist for these
   days). Features: its 9. Estimator: LightGBM binary, 120 rounds. Metric: AUC vs 0.5. Short history (≤ 6 events ×
   ~20 days) → **not validated**; exploratory weekly if ≥ 60 events with ≥ 10 of each class.
5. **variant_bandit** — Thompson ranking of arms by posterior P(profitable day). **Not validated**: it has no
   supervised label and no features; a ranking's quality is a decision test that would need months of forward
   weeks (and its `day_table` mixes every paper label, so replay labels of the same ids would count as pulls).
6. **exit_model** — per 30-s path sample, is the remaining move positive. Dataset: the model's own `_rows()` over
   `base.trade_paths()`. Deviation decided here: `trade_paths` keeps the LAST 600 closed trades of every label,
   which at 6,655 strategies is a single session; the harness instead feeds it a seeded (seed 7) random sample
   of ≤ 1,500 closed tradeify + all live trades spread over the 4 weeks (`closed_trades` is patched to that
   sample inside the harness only; trades held longer than 4 h are excluded from the sample — a multi-session
   hold is millions of ticks and the model's own exit logic caps nothing). Features: its 11. Estimator: LightGBM binary, `min_data_in_leaf =
   max(10, n // 40)`, 120 rounds. Metrics: AUC vs 0.5 (primary), and the model's own stall-rule replay (flatten
   the first time p < 0.35 while ahead) as net P&L per trade vs letting the trail run (decision metric,
   reported). Split by trade week. Short history → **not validated**; exploratory weekly.
7. **regime** — k-means on hourly bar features. **Not validated**: unsupervised, no label to shuffle or score.
8. **fill_quality** — live entry slippage (ticks) and time-to-fill (ms). Dataset: `fill_quality.dataset(days=40)`
   (85 live trades). Features: its 7. Estimators: two LightGBM regression_l1, 120 rounds. Metrics: slippage MAE vs
   training median (primary), fill-ms MAE (secondary). 85 rows / 4 weeks → **not validated**; exploratory weekly
   only if every fold has ≥ 20 training rows.
9. **policy_search** — grid of trail / break-even / time-stop policies replayed on tick paths, chosen on earlier
   trades. **Not validated** as a supervised model (no features, no labels). For orientation only: the policy
   chosen on the same paths' earlier weeks (`policy_search.replay`, its own grid) is scored on the later weeks
   as net P&L per trade vs the actual exits, plus the spread of 20 randomly drawn policies as the control.
10. **sequence** — GRU, p(close 5 bars ahead > now) from the last 30 bars. Reduced protocol, fixed here for the
    time-box: bars 2022-01-01 → 2026-10-17 through the same per-year loader; the model's own `_frames` and
    `_net`; folds test 2024, 2025, 2026 (train = all earlier frames from 2022, capped at the most recent
    200,000 frames); Adam 2e-3, batch 512, at most 6 epochs with early stopping on the LAST 10 % of the
    training frames (never the test fold); GPU when available. Shuffled refits: **5 per fold** (not 20 —
    stated). Feature importance: the 4 per-step channels (ret, range, vol-z, minute-of-day), each permuted across
    all 30 steps, 10 seeds. Metric: AUC vs 0.5 (pass metric), accuracy vs majority reported. If a single real
    fit exceeds 4 min, the model is marked not validated (too slow).
11. **exit_optimizer** — best (break-even trigger, trail step, delay) per engine × session chosen on earlier days.
    **Not validated** as a supervised model (decision rule, no features). Orientation only, on a seeded sample
    of ≤ 600 ORB/trend tradeify + live trades: the harness builds each trade's 1-minute path with the model's own
    SQL (its `_paths` runs one tick query per trade for every label in range, which is not runnable) and reuses
    `exit_optimizer.simulate` / `_session`; weekly: the rule chosen on earlier weeks is scored on the next week
    as $/trade vs the live rule (3 / 10 / 300), vs actual, and vs 20 random rules.
12. **signal_meta** — p(P&L > 0) for a base strategy's taken signal from the book at the signal. Dataset:
    `signal_meta.dataset(days=40)` (19,986 rows). Features: its 11. Estimator: LightGBM binary, 120 rounds.
    Metric: AUC vs 0.5; its gate backtest (take if p ≥ 0.55: P&L taken vs all) reported as the decision view.
    Short history → **not validated**; exploratory weekly.
13. **overlay_uplift** — per overlay, paired value vs base by context, plus a LightGBM regressor when ≥ 300 rows.
    Dataset: `overlay_uplift.dataset(days=40)`. Validated piece: the regressor (features spread, imbalance, hour,
    eng_orb, eng_trend; its own params, 200 rounds) per overlay with ≥ 300 rows, MAE vs training mean. The
    bootstrap context table is descriptive and not scored. Short history → **not validated**; exploratory weekly.
14. **fill_cost** — $ cost of the bid/ask book per paper trade. Dataset: `fill_cost.dataset(days=40)` as written
    (every non-audit label with a shadow fill in range — rows from replay labels without quotes carry cost 0 and
    NaN spreads; their share is reported). Features: its 14. Estimator: LightGBM regression_l1, 120 rounds.
    Metric: MAE vs training mean. Short history → **not validated**; exploratory weekly.

## What a result may and may not say
A PASS here means "this model's features carry out-of-sample information beyond chance under a yearly
walk-forward"; it says nothing about tradability or cost. A FAIL means the opposite for this feature set and
estimator. "Not validated — short history" means exactly that: the trade-based zoo has 23 sessions, and nothing
run on 23 sessions is evidence either way. Working-feature lists are the output that survives this study; the
refit-on-working-features metric is reported, not optimised.
